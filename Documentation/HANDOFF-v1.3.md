# Rhythm v1.3 引き継ぎ（2026-10-12 合意）

モック：`Preview/ui-v1.3.html`（Artifact https://claude.ai/artifact/1G2iAXT6AUZWgcQWWohxzh）。本人回答：スクリーンタイムは**案A**、ゲートの症状は**(a) SNSが普通に開けてしまう**。

## A. 今日のスクリーンタイムカード（案A）
対象：`ScreenTimeReport/ScreenTimeReport.swift` の `TodayCardScene` / `TodayCardView`、`Rhythm/TodayViews.swift` の `TodayScreenCard`。

- 主役は「今日のSNS ◯分 / 目標◯分」の1つだけ。右に状態の札「いつもより N分少ない／多い」（±1分未満は「いつもと同じ」）。
- ゲージ1本：0〜目標。塗り＝今日のSNS、縦の目印＝いつもの同じ時刻までの平均（ラベル「いつもの13:32 ＝ 29分」）。塗りは平均以下なら緑、平均より多い時だけ朱。目標超過時は満タン＋「+N分 超過」。
- 目標以下の連続日数（P4）は、1日以上の時だけ2つ目の札「目標以下 N日連続」で出す。0日なら出さない。
- 時間帯別のSNS：24本（0〜23時）、今日＝塗り、いつも＝薄い棒、今の時間を強調。軸ラベルは0/6/12/18時。
- 下段3つ：合計（平均との差）／持ち上げ（同じ時刻までの平均との差。Bで追加）／最初のSNS（いつも ◯時台）。
- 外すもの：4区分の凡例と横棒（詳細画面にある）、今日／平均の比較棒、「平均＝過去7日…」の説明文（設定の「数字の見方」へ移す）、本体側の「うち仕事目的」（詳細画面のP5にある）。
- リンク文言：「アプリ別・持ち上げ・時間帯を見る」。
- カードの高さ（今は `@ScaledMetric 330`）は内容に合わせて見直す。
- **不具合修正**：最初のSNSの平均が「3.6時」になる。`HealthMath.firstHour` が0時から探すため、夜ふかし（0〜3時台）がその日の「最初」になって平均が崩れている。**4時以降の最初の利用**で数え、過去日は**中央値**にする。「数字の見方」の説明も合わせる。テストを追加。

## B. 持ち上げ回数（起動回数の代わり）
Appleはロック解除回数を渡さない。表示拡張の `DeviceActivityData` から読む（追加の許可・Apple側登録は不要）。

- 区間ごとの回数＝各アプリの `numberOfPickups` の合計＋`ActivitySegment.totalPickupsWithoutApplicationActivity`（＝「見ただけ」）。
- アプリ別の `numberOfPickups`＝持ち上げて最初に使ったアプリ。分類（SNS等）も付けて集計し、SNS起点の割合を出す。
- 今日のカード：下段に「持ち上げ N回 ↓/↑差」（いつもの同じ時刻まで）。
- 詳細画面（`DetailScene`）：今日／7日／30日平均の回数、1回あたりの利用時間（合計÷回数）、時間帯別の棒、最初に開いたアプリの順位（上位5＋見ただけ）、ヒント1行「持ち上げの◯%（N回）がSNSから。いちばん多いのは◯時台」。
- 振り返り：6つ目の指標「持ち上げ」を一覧・グラフ・カレンダーに追加（週・月・3か月・年）。シーンは1ブロック10個までなので新しいブロックに分ける。
- 値は表示拡張の中だけで扱う（ウィジェット・通知には出さない。SNS分数と同じ）。
- 実機で確認：1時間単位で回数が0にならず取れるか。取れなければ1日単位の回数だけにして時間帯別は出さない。

## C. SNSゲート：SNSが普通に開けてしまう（症状a）
**原因：設定でオフのままだった（10/12本人確認）。** コード上（オン→`GateShield.apply`→`ManagedSettingsStore(named: .rhythmGate)`、復帰時の `restoreIfDue`、解除の15分最小枠）にも誤りは見つかっていない。以下は優先度を下げ、2（オフの見落とし防止）と4（通知に頼らない導線）を先に入れる。1・3は、オンにした後の実機確認で通知（③）以降が止まった場合に入れる。

1. **ゲートの状態チェック**（設定の「開く前に、ひと呼吸」内に1画面）：オン／オフ、スクリーンタイムの許可（`AuthorizationCenter.authorizationStatus`）、通知の許可、設定ファイル上の対象数（アプリ・カテゴリ・サイト）、**実際の遮断の対象数**（`ManagedSettingsStore(named: .rhythmGate).shield.applications/applicationCategories/webDomains` を読み返す）、解除中の終了時刻、監視中の名前（`DeviceActivityCenter().activities`）、最後にシールドのボタンが押された時刻。「遮断をかけ直す」ボタン（`GateShield.apply`）も置く。
2. **オフの見落とし防止**：今日の「SNSゲート」カードがオフの時は「オフです」と明示し、設定へ飛ぶボタンを出す。
3. **オンにした直後の検証**：`enable` と `selectionChanged` の後に遮断の対象を読み返し、空なら「遮断をかけられませんでした」を出す。
4. **通知に頼らない導線**：シールドの「理由を選んで開く」で押した時刻を App Group（`Gate/` の設定と同じ保護）に残し、5分以内にRhythmを開いたら目的選択を自動で出す。シールドの副題に「通知が来ないときはRhythmを開いてください」。ウィジェットのタップで `rhythm://gate` を開く。
5. 本人の実機確認の順番：状態チェックを開く → オンか・対象数が0でないか・許可が承認か → X/Instagramを開いてシールドが出るか → 「理由を選んで開く」→通知→選択画面。
